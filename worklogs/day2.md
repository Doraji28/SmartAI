# [Day 2 Worklog] OSU 스타일 2D 노트 및 어프로치 링 도입

## 1. 개발 목표
- 복잡한 3D 가상 슈팅 조준 방식이 리듬 게임 고유의 타격 피드백과 동떨어지는 문제를 해소하기 위해, 화면 여러 위치에 무작위 및 시간차를 두고 나타나는 OSU 스타일의 2D 서클 노트 방식을 구현합니다.
- 시간이 지날수록 노트 중심을 향해 수축하는 타이밍 안내 링(Approach Ring) 및 클릭 입력에 대한 정밀도 판정을 구현합니다.

## 2. 핵심 구현 내용 및 세부 설계
- **노트 모델링**: 화면 배치용 2D 노트 오브젝트(X, Y, Target Beat) 데이터를 설계하고 관리 풀을 구성했습니다.
- **수축 링 연출**: 비트와 음악 재생 시간에 비례하여 반지름이 좁혀지는 `Approach Ring` 공식과 수식 애니메이션을 구현했습니다.
- **입력 감지**: 마우스 좌표와 노트 좌표 간 유클리드 거리(`Euclidean Distance`)를 측정해 클릭 지점이 반지름 이내인지를 검증하는 원형 충돌 판정을 작성했습니다.

## 3. AI 에이전트 협업 & 프롬프트 예시
- **프롬프트**: "마우스를 클릭했을 때 화면에 배치된 노트의 좌표를 기준으로 마우스가 클릭한 위치와의 거리를 구해 반지름 이내인지 체크하는 충돌 체크 함수를 작성해줘. 그리고 노트와 판정 링이 겹치는 시점에 맞춰 PERFECT, GOOD 판정을 구분하게 해줘."
- **협업 내용**: 에이전트는 피타고라스 정리 기반의 좌표 거리 연산(`dx^2 + dy^2 <= r^2`)과 오프셋 델타 시간차를 분석하여 정밀 판정을 수행하는 기초 로직을 제공했습니다.

## 4. 디버깅 및 검증 과정
- **문제점**: 노트가 한 번 클릭된 후에도 입력 버퍼가 초기화되지 않아 매 프레임 다중 히트로 판정되거나, 판정이 끝난 노트가 지워지지 않고 계속 남아 오류를 범했습니다.
- **해결 및 검증**: 각 노트에 `hit_evaluated` 상태 플래그를 추가하고 판정이 완료된 즉시 노트 관리 배열 테이블(`note.active_notes`)에서 제외시키도록 큐(Queue) 구조로 안전하게 리팩토링했습니다.

## 5. 핵심 소스코드 블록 및 설명 (`note.lua` 발췌)
```lua
-- 마우스 클릭 시 충돌 거리와 오디오 타이밍 시간차를 이용한 판정 연산
local dist_px = math.sqrt((mx - n.screen_x)^2 + (my - n.screen_y)^2)
local hit_radius = 90 -- 판정 반지름 영역

if dist_px <= hit_radius then
    local beat_dist = math.abs(current_beat - n.target_beat)
    local time_offset = beat_dist * beat_interval
    
    local rating = "BAD"
    if time_offset <= 0.15 then
        rating = "PERFECT"
    elseif time_offset <= 0.28 then
        rating = "GOOD"
    end
    -- 판정이 끝난 노트는 제거 및 피드백 처리 진행
end
```
