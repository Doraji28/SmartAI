# [Day 3 Worklog] 오디오 동기화 보정 및 클릭 버그 디버깅

## 1. 개발 목표
- 프레임 델타 타임(`dt`)의 미세 누적으로 인해 음악과 노트 어프로치 링 타이밍이 서서히 어긋나는 오디오 디싱크(De-sync) 문제를 바로잡습니다.
- 클릭 판단에 있어 입력 신호 딜레이나 중복 합산 판정이 생기는 입력 버그들을 완벽하게 개선합니다.

## 2. 핵심 구현 내용 및 세부 설계
- **하드웨어 재생 시간 클록 동기화**: 기존 프레임 타임 합산 방식을 폐기하고, 사운드 카드의 하드웨어 재생 스탬프인 `source:tell()` 값을 직접 질의하여 게임 비트 오프셋 계산의 절대적 기준으로 삼았습니다.
- **중복 입력 원천 차단**: 하나의 노트가 단일 프레임 윈도우 내에서 중복해서 클릭 이벤트가 중첩 처리되지 않도록 입력 차단 처리를 강화했습니다.

## 3. AI 에이전트 협업 & 프롬프트 예시
- **프롬프트**: "매 프레임 dt를 더해서 음악 싱크를 맞췄더니 뒷부분 곡에서 링 수축 속도가 점점 밀려. 오디오 카드의 실제 재생 위치를 알려주는 love.audio 소스 내부 함수가 뭐야? 그걸 기준으로 비트 계산식으로 변경해줘."
- **협업 내용**: 에이전트는 `tell()` 함수를 통해 사운드의 물리적인 재생 초(Second) 단위를 구하고, 곡의 BPM 정보와 시작 오프셋을 조합하여 수학적 무오차 실시간 비트 연산식을 제시했습니다.

## 4. 디버깅 및 검증 과정
- **문제점**: 마우스를 빠르게 연속 클릭하거나 한 번 길게 누를 때, 의도치 않게 단일 프레임 내에서 두 번 이상 클릭 감지가 중복되어 판정 사운드가 겹치고 점수가 다중 가산되는 버그가 확인되었습니다.
- **해결 및 검증**: 마우스 입력 시점을 프레임 업데이트 루프가 아닌 `love.mousepressed` 이벤트 콜백 인터럽트로 이전 설계하고, 단 한 번의 단일 판정만 이루어지도록 노트 삭제(Remove)와 판정 완료 플래그 처리를 하나의 트랜잭션으로 묶어 완전히 해결했습니다.

## 5. 핵심 소스코드 블록 및 설명 (`main.lua` 발췌)
```lua
-- [3일차 수정] 하드웨어 사운드 카드 재생 위치를 절대 기준으로 실시간 동기화
local music_time = sound_synth.music_loop:tell()

-- 오프셋 차감 후 비트 간격(60 / BPM)으로 나눠 소수점 형태의 실시간 비트 흐름 계산
beat_manager.current_beat = (music_time - beat_manager.track.start_offset) / beat_manager.beat_interval
```
